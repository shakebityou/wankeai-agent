### 账号体系在哪

账号、角色、分组、密码哈希、会话、审计日志**全部落 SQLite**：

```
frontend/mock/db/wankeai.db        ← 运行时自动生成，首次启动写入 7 个种子账号
frontend/mock/db/schema.sql        ← 建表语句（roles/groups/users/auth_sessions/audit_log）
frontend/mock/seed/auth-db.ts      ← 种子账号与统一演示口令
frontend/mock/services/auth-service.ts  ← 登录/锁定/改密/用户 CRUD 的业务逻辑
frontend/mock/handlers-auth.ts     ← /bff/v1/auth/* 与 /bff/v1/users/* 路由
```

几个刻意的设计：

- **密码用 scrypt + 每账号独立 salt**（`mock/db/password.ts`），库里存的是 `scrypt$N$r$p$salt$hash`，`toView()` 永远不返回哈希字段。
- **连续 5 次密码错锁 10 分钟**（`MAX_FAILED_ATTEMPTS` / `LOCK_MINUTES`），登录页会显示倒计时并禁用按钮。
- **账号不存在时也跑一次哈希比对**（`DECOY_HASH`），避免用响应时间做账号枚举；提示文案与密码错完全一致。
- **会话是 HttpOnly Cookie `wk_session`**，库里只存它的 sha256，不存明文。
- **改密/重置密码/禁用账号会吊销该账号全部在线会话**。
- **管理员不能改自己的角色、不能禁用自己**（防止把最后一个管理员锁死在外）。
- 所有登录、改密、账号增删改都写 `audit_log`，可在「账号管理」页底部查看。

**删库重置**：停掉 dev 服务 → 删 `frontend/mock/db/wankeai.db*` → 重启即可回到 7 个种子账号。

### 联调真实 BFF

```bash
VITE_BFF_TARGET=http://10.0.1.20:8000 npm run dev
```

设置后 `vite.config.ts` 会把 `/bff` 前缀代理到该地址，前端代码**一行不用改**。
这也是「前端只调 BFF」这条红线的工程价值：换后端只改一个环境变量。

真实 BFF 接上后，账号与会话由后端负责，本地的 `mock/db/` 不再参与，
但**接口契约不变**（`/bff/v1/auth/login` 等，见 `src/api/auth.ts`），前端无需改动。

### 三条不可越过的线

1. **`src/api/` 之外不许出现 `axios` / `fetch` / `EventSource`。**
   想让 `lint:compliance` 放过你，先改这条线。
2. **`src/types/contract.ts` 是契约唯一真源。** 后端改字段先改这里；
   改完 `typecheck` 会把所有受影响的地方指出来。
3. **Mock 与 `src/api/` 必须同口径。** Mock 返回 `FAQ-0001` 而前端拼 `KB-FAQ-001`，
   这种错只有联调才暴露——所以 Mock 直接复用 `src/types/contract.ts` 的类型。

## 四、故障排查表

### 4.1 构建相关

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| `[vite:esbuild-transpile] remove ...: Access is denied` | esbuild 把临时文件写到系统 `%TEMP%`，受限环境删不掉 | 已由 `scripts/build.mjs` 把 `TMPDIR/TEMP/TMP` 指到 `.esbuild-tmp/`。**不要绕过脚本直接跑 `vite build`** |
| `vue-tsc` 报模板里的 TS 语法错 | Vue 模板表达式不支持类型标注 | 把类型化逻辑放进 `<script>`，模板只调函数名。`<el-table-column #default="{ row }">` 的 `row` 是 `any`，用 `(row as KbChunk)` 收窄 |
| 构建产物 element-*.js 有 900 kB | Element Plus 全量引入 | 当前可接受（gzip 289 kB）。若要优化，改按需引入，但会牵动 `src/main.ts` 与所有组件 |

### 4.2 运行相关

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| **侧栏图标撑满整屏**（一列巨大的 ⌄ / 时钟 / 叉），下拉框塌成一条，表格没有边框 | `<ElConfigProvider>` 上设了 `namespace="wk"`，组件类名变成 `wk-select`，而样式表只认 `.el-select` | **不要在 `App.vue` 里设 namespace**。要定制外观走 `src/styles/index.scss` 的 CSS 变量覆写。已修，勿回退 |
| 控制台报 `EvalError: Refused to evaluate a string as JavaScript` | `script-src 'self'` 封掉了 Vue 运行时模板编译所需的 `unsafe-eval` | `vite.config.ts` 的 `devCspPlugin` 只在 dev 注入 `'unsafe-eval'`；生产已预编译模板，不需要 |
| 列表报「Mock 处理异常：ENOENT ... mock/seed/data/xxx.json」 | `data-loader.ts` 的 `DATA_DIR` 定位错 | 应为 `join(here, '..', 'data')`（数据在 `mock/data/`，loader 在 `mock/seed/`） |
| 登录后立刻跳回登录页 | Cookie `wk_session` 没种上或已过期 | DevTools → Application → Cookies 看是否过期/被 Secure 标记拦掉。本地 http 环境下 Cookie 不带 `Secure` |
| 登录后落到「无权限访问」而不是角色首页 | 同标签页换人登录时残留了上一个人的 `?redirect=`，且目标页超出新角色权限 | 已修：`gotoLanding` 按**目标路径**校验权限，且 `/` 占位路由不参与判定 |
| 登录后所有角色都落到同一个页面 | `?redirect=/` 被解析成无 `meta.permission` 的占位路由，被误判为「通过校验」 | 已修（同上）。`/` 是重定向占位，不能当落地目标 |
| 提示「账号已锁定，请 N 分钟后重试」 | 连续 5 次密码错触发了锁定（`MAX_FAILED_ATTEMPTS=5` / `LOCK_MINUTES=10`） | 等 10 分钟自动解锁，或让管理员在「账号管理」里把状态改回启用 |
| 提示「这是初始密码，请先修改密码」 | 账号 `must_change=1`（新建账号/被重置密码后） | 正常流程：到改密页设置新密码后才能进系统 |
| 管理员改不了某个账号的角色 | 试图改**自己**的角色 | 有意为之，防止把最后一个管理员降级后全组失联。请用另一个管理员账号操作 |
| 种子账号全没了 / 想回到初始状态 | —— | 删 `mock/db/wankeai.db*` 后重启 dev 服务 |
| 页面白屏，控制台 `Failed to fetch dynamically imported module` | 发版后旧 `index.html` 指向已删除的旧 chunk | 确认 Nginx 对 `index.html` 设了 `no-store`，让用户强刷 |
| 打字机「憋一段再全吐出来」 | SSE 被代理缓冲 | 后端要发 `X-Accel-Buffering: no`；Nginx 要 `proxy_buffering off`（`deploy/nginx.conf` 已配） |
| 消息流不自动滚到底 | 坐席上滚超过 48px，触发了「暂停自动滚」 | 这是设计行为。点右下「回到底部」按钮恢复 |
| AI 上下文卡整块变成「上下文生成异常」 | 七要素缺项（守卫生效） | 看卡片列出的缺失项，直接告诉后端。这是**有意的失败**，不要试图绕过守卫 |

## 五、合规红线与检查机制（最重要的一节）

三条硬约束贯穿整个前端，任何一条违反即验收不通过。

### 5.1 HC-1 不外链

**要求**：不生成、不发送任何外链或跳转卡片；前端不渲染可点击链接；话术不得出现「我把链接发您」。

**工程落地**：

| 层 | 手段 |
| --- | --- |
| 输入 | `utils/message-kind.ts` 的 `containsUrl` / `stripUrls`，命中的 URL 替换为「[链接已屏蔽]」 |
| 渲染 | `MessageBubble` 不用 `v-html` 渲染外部文本；`KbEditor` 预览里裸 URL 显示「[链接已屏蔽]」、`<a href>` 被转义 |
| 图片 | `ProductRefCard` / 附件图**不可点击**，无 `a` 包裹 |
| 订单 | `OrderTextCard` 是**纯文本**模板，不是卡片跳转 |
| 静态扫描 | `lint:compliance` R1：全仓扫 URL，平台域名（taobao/tmall/pdd/douyin/weixin）零容忍 |
| 运行时 | E2E `expectNoAnchor()`：真浏览器里 `a[href]` 只能是 `#` 锚点 |

### 5.2 HC-2 数据最小必要、日志零敏感

- 脱敏函数在 `utils/format.ts`：`maskPhone('13812345678') → '138****5678'`（后 4 位）、
  `maskName('张小明') → '张**'`、`maskOrderNo → '2025****2345'`、`maskAddress` 保留到「市」。
- **坐席可见完整，但不可导出**——所以整个仓没有 `download` 属性、没有 `file-saver`、没有 `window.print()`。
- 埋点只写 `sessionStorage`，不上报任何买家字段。

### 5.3 HC-3 会变的数走接口

- 库存 / 价格 / 物流单号一律来自接口，**前端不写死任何数值**。
- 这些字段**不进向量库**：`mock/seed/kb.ts` 的 `buildKbChunks` 只用商品名、卖点、洗护等稳定知识。
- 无依据时 `KbSearchPanel` 显示「知识库中没有依据 + 请勿凭记忆作答」。

### 5.4 为什么单测文件不参与合规扫描

`scripts/compliance-check.mjs` 里有一行：

```js
const TEST_FILE = /\.(test|spec)\.(ts|tsx|js|mjs)$/
```

因为**单测必须构造反例才能验证红线**：`KbEditor.test.ts` 要输入一条真的淘宝链接
才能断言它被屏蔽；`format.test.ts` 要输入真的手机号才能断言脱敏正确。
把它们纳入扫描只会得到 5 条必然误报。

## 六、性能基线（任务书 4.5）

| 指标 | 目标 | 当前 | 手段 |
| --- | --- | --- | --- |
| 首屏 P95 | ≤2s | 待真实环境测 | 代码分割（`manualChunks` 拆 vue/element/charts）+ gzip 675 kB |
| 消息流 500 条 | ≥50fps | 待真实环境测 | 只追加不重排；打字机文本独立渲染 |
| AI 上下文渲染 | ≤200ms | 待真实环境测 | `guardContext` 是 O(7) 的同步检查，无额外请求 |
| 知识检索 | P95 ≤500ms | Mock 下 <50ms | 300ms 防抖 + 请求序列号丢弃过期响应 |
| 前端超时 | 10s | `REQUEST_TIMEOUT_MS = 10000` | `src/api/client.ts` |
| 骨架屏 | 超 1s 才出现 | `SKELETON_THRESHOLD_MS = 1000` | `useAsyncData` —— 快请求不闪骨架 |

**关于骨架屏阈值的取舍**：1 秒内返回的请求如果也闪骨架，用户会看到
「白 → 骨架 → 内容」三次跳变，比直接等一下更难受。所以只在超过 1 秒时才切骨架。

## 七、Mock 的用法（联调前的主要开发形态）

Mock 不是「假数据占位」，而是**契约的可执行副本**。

### 注入异常场景

```bash
# 让会话列表报 500
curl 'http://127.0.0.1:5273/bff/v1/sessions?__fail=40001'

# 让接口慢 3 秒（验证骨架屏与 loading）
curl 'http://127.0.0.1:5273/bff/v1/sessions?__delay=3000'

# 让 SSE 吐 error 事件（验证降级提示）
#   浏览器里访问：/bff/v1/chat/stream?__sse=error

# 让 SSE 吐 handoff 事件（验证转人工卡片）
#   浏览器里访问：/bff/v1/chat/stream?__sse=handoff
```

`__fail` 支持 `10001/10002/10003/10004/10005/20001/30001/40001`，
正好覆盖全部 BFF 错误码，用来验证拦截器的 6 个钩子。

### 数据从哪来

`mock/data/*.json` 由 `scripts/extract-merchant-data.py` 从商家材料包提取，
**不是手写的**。重新生成：

```bash
python scripts/extract-merchant-data.py
```

生成结果的口径（已实测）：

| 文件 | 条数 | 说明 |
| --- | --- | --- |
| `products.json` | 74 | 商品知识卡，正文去空白后 213–249 字，全部落在 200–400 区间 |
| `faqs.json` | 126 | 标准问 + 答案 91–200 字，全部落在 50–200 区间 |
| `history-sessions.json` | 324 | 历史会话语料，用于造会话列表与指标 |

> **注意**：因为真实数据全部合规落在区间内，FE-06 的「超长/过短标记」
> 无法用商品/FAQ 数据演示，需要靠长文档类型或人工构造超长行触发。
> 这是数据特性，不是缺陷。

## 八、契约变更流程

后端要改接口时：

1. **先改 `src/types/contract.ts`**（唯一真源），跑 `npm run typecheck` 看波及面。
2. 同步改 `mock/handlers.ts` 的返回，保证 Mock 与契约一致。
3. 补/改单测中受影响的部分。
4. 跑全量：`typecheck + test + lint:compliance + build + test:e2e`。
5. 在 `_parts/02_接口契约设计.md` 记录变更（这是与后端共用的真源文档）。

**不要**先改页面再补类型——`vue-tsc` 会把 `any` 传染到组件，最后没人敢改。

## 十、本机踩坑记录（省下后来人的时间）

1. **npm 缓存必须在工作目录内**：`.npmrc` 设了 `cache=D:/learn/homework/agent/.npm-cache`，
   否则受限环境下会报 `EPERM`。
2. **不能在本环境用 `curl.exe` / `Invoke-WebRequest` 探测 npm 源**：
   报 `schannel SEC_E_NO_CREDENTIALS`。改用 `npm` CLI 本身。
3. **esbuild 临时目录**：见 4.1，已由 `scripts/build.mjs` 解决。
4. **单测白名单口径**：`vitest.config.ts` 的 coverage `include` 只列已有单测的路径。
   把 `src/**/*.{ts,vue}` 全量纳入会让全局覆盖率掉到 21.6%（被大量 0% 未测组件稀释），
   于是「单测管逻辑与核心组件、E2E 管页面与关键路径」，各自设阈值。
5. **`el-dialog` 的标题在 `.el-dialog__title` 里**，Playwright 的 `locator('.el-dialog', { hasText })`
   抓不到，要用 `getByRole('dialog', { name })`。
