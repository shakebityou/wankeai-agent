# 玩可爱智能客服 Agent —— 前端组件库文档

> 对应任务书 4.6 交付物第 2 项「组件库文档」。
>
> 本文档不是 API 手册的复制，而是回答三个问题：
> **这个组件为什么存在、什么场景该用它、用错会出什么事。**

---

## 0. 阅读前提

### 0.1 技术栈边界（任务书 4.1）

| 项 | 选型 | 为什么 |
| --- | --- | --- |
| 框架 | Vue 3.5 + TypeScript 5.6 | 任务书锁定 |
| 构建 | Vite 5 | 冷启动快，SSR 本期不需要 |
| 状态 | Pinia | 只有 `auth` 一个 store，够用 |
| UI 库 | Element Plus 2.9 | 表格/表单/弹窗不自己造轮子 |
| 图表 | ECharts 5 | 看板与容量图 |
| 流式 | 原生 `EventSource`（SSE） | 任务书明确不引入 WebSocket |

**明确不引入**：微前端、自研组件库、WebSocket、移动端适配。

### 0.2 目录约定

```
src/components/<分组>/<组件>.vue
src/components/<分组>/<组件>.test.ts   # 单测与被测文件同目录
```

组件**按业务域分组**，不按原子/分子/有机体分层。理由：坐席台的组件几乎没有跨域复用
（`MessageBubble` 不会出现在运营后台），按域分组后，删一个业务就删一个目录，比
Atomic Design 的「改一处动三层」更好维护。

### 0.3 命名与样式

- 根节点类名 = 组件语义（`.metric` / `.upload` / `.rules`），BEM 的块。
- 内部元素一律 `&__xxx`（`.metric__name`、`.metric__status`）。
- 状态修饰符 `--xxx`（`.metric--ok` / `.metric--warn` / `.metric--bad`）。
- **不写内联 style**，颜色/间距/字号一律走 `src/styles/tokens.scss` 的设计令牌。
- 全局原子类在 `src/styles/index.scss`：`.wk-page` / `.wk-card` / `.wk-pill--ok|warn|bad|info|brand|mint|neutral` / `.wk-mono` / `.wk-no-print`。

## 1. 通用组件（`common/`）

### 1.1 `PageState` —— 三态占位

**作用**：统一 loading / empty / error 三态。

**为什么必须有**：任务书 4.6 DoD 要求「UI 走查通过（含空态/错误态/加载态三态）」。
坐席台有 5 个列表、后台有 8 个页面，如果每处各写一套「转圈 / 无数据 / 报错」，
留白和文案立刻散掉。

```vue
<PageState v-if="loading" state="loading" title="正在加载会话" />
<PageState v-else-if="error" state="error" :detail="error.message" retryable @retry="reload" />
<PageState v-else-if="!items.length" state="empty" title="暂无会话" description="换个筛选条件试试" />
```

**要点**：
- `state="error"` 时**必须**传 `retryable` + `@retry`，否则用户只有刷新浏览器一条路。
- `detail` 放 BFF 返回的 `message`，不要拼自己的猜测。
- 不要用它做「加载中骨架」——超 1 秒的加载用 `useAsyncData` 的 `showSkeleton`。

### 1.2 `SectionCard` —— 带标题的内容卡

右栏三块（AI 上下文 / 知识检索 / 买家信息）都用它包，保证标题层级与间距一致。

```vue
<SectionCard title="AI 上下文">
  <ContextCard :context="ctx" :session-id="id" />
</SectionCard>
```

### 1.3 `EnumTag` —— 枚举中文标签

契约里的枚举（`channel` / `order.status` / `priority` …）在 `src/types/contract.ts`
里都有 `*_LABELS` 映射。**不要**在模板里直接展示英文枚举值。

```vue
<EnumTag kind="tone" value="ok" label="已通过" />
```

## 2. 会话工作台（`session/`）

### 2.1 `MessageStream` ★ 核心组件（单测覆盖率要求 ≥80%，实测 96.4%）

**作用**：实时消息流 + SSE 打字机 + 上滚暂停自动滚底。

**关键设计决策**：

1. **自动滚底是有条件的**，不是无脑 `scrollTop = scrollHeight`。
   坐席往上翻历史消息时，新消息进来就把他弹回底部，是不可接受的。
   实现上比较「距底距离」与 `BOTTOM_TOLERANCE_PX = 48`，超出就暂停自动滚，
   并在右下角显示「回到底部」按钮（`.stream__jump`）。

2. **打字机文本不进入消息列表**。`streamingText` 单独渲染在
   `.stream__streaming`，不 push 进 `messages`。理由：`turn.end` 的完整 `reply`
   才是落库口径（契约 2.5.4），如果 `delta` 直接进列表，`turn.end` 到达时会
   出现「同一条消息出现两遍再消失」的闪动。

3. **错误态必须给可执行的下一步**。`.stream__error` 的文案是
   「请直接接管回复买家」，而不是「加载失败」。

```vue
<MessageStream
  :messages="messages"
  :loading="detail.loading.value"
  :typing="stream.typing.value"
  :streaming-text="stream.streamingText.value"
  :stream-error="stream.streamError.value"
  @retry-stream="stream.retry"
  @feedback="markFeedback"
/>
```

**`defineExpose`**：`resetToBottom()` / `backToBottom()`，切换会话时由父组件调用。

### 2.2 `MessageBubble`

单条消息气泡。通过 `resolveMessageKind()`（`src/utils/message-kind.ts`）推导渲染类型：

| kind | 判定 | 渲染 |
| --- | --- | --- |
| `HANDOFF_CARD` | 有 `handoff_reason`（优先级最高） | 转人工卡片 |
| `OCR` | `text_source === 'OCR' \| 'VLM'` | 订单截图识别结果 |
| `VOICE` | `text_source === 'ASR'` | 语音转写 + 标记 |
| `IMAGE` | `msg_type === 'IMAGE'` | 图片，**不可点击打开**（HC-1） |
| `TEXT` | 其余 | 纯文本 |

**HC-1 落地**：气泡内**不渲染任何 `<a>`**。若文本含 URL，由 `stripUrls()` 替换为
「[链接已屏蔽]」。这一点由单测 `wrapper.find('a').exists() === false` 与
E2E `expectNoAnchor()` 双重把守。

### 2.3 `TakeoverButton` ★ 核心组件

**作用**：一键接管 / 释放（FE-03）。

**三个设计决策**（源码注释里也写了，这里提炼）：

1. **冲突不交给全局拦截器**。10005 需要做三件事：提示「已被 XXX 接管」、
   立刻刷新会话状态、把按钮切回正确形态。全局拦截器只能弹一句通用提示。

2. **按钮文案随归属变化**，不常驻两个按钮：
   - 未接管 → 「接管会话」
   - 我接管 → 「释放回机器人」
   - 他人接管 → 禁用 + 「已被 {agent_name} 接管」

   从 UI 上就杜绝了「别人正在处理，我还去点接管」的误操作。

3. **无权限时隐藏而不是点了才报 10003**。`allowed` 由 `canDo(role, 'takeover.execute')` 决定。

### 2.4 `KbSearchPanel` —— 知识检索侧栏（FE-04）

- **300ms 防抖**，回车立即搜。
- **只展示 `APPROVED` 且 `effective_to === null`** 的条目（后端已过滤，前端不做二次信任）。
- **一键填入不改原文**：`emit('fill', hit.content)`，原文直出。
- 命中为空时**不显示空列表**，而是显式的「知识库中没有依据 + 请勿凭记忆作答」
  （对应 HC-3 无依据必须拒答）。
- 每条命中展示 `score`（两位小数）+ `authority`（「依据：商品主数据表·洗护方式字段」）。

### 2.5 其余

| 组件 | 场景 |
| --- | --- |
| `SessionList` | 会话列表，30 秒轮询 + 未读红点 |
| `SessionFilter` | 渠道/分组/接管状态/时间区间/关键词 |
| `OwnerBadge` | 机器人 / 坐席归属徽标，含「机器人已静音」标记 |
| `ConfirmDialog` | 接管/释放的二次确认，必须列出操作后果 |
| `TypingIndicator` | 机器人思考中的阶段提示（检索知识库 / 生成回复） |

## 3. AI 上下文卡片（`context/`）★ FE-02 优先项

### 3.1 `ContextCard` —— 七要素守卫（单测覆盖率要求 ≥80%，实测 100%）

**作用**：渲染 AI 上下文七要素；**缺一即整卡报错**。

**为什么是「整卡报错」而不是「缺哪块不渲染哪块」**：
缺字段的上下文会主动误导坐席。比如缺 `unmet_demand`，坐席会以为买家没有未满足
诉求；缺 `verified`，坐席会把模型幻觉当成已核实事实。**错误态比半张卡片安全**。

**守卫口径**（`src/utils/context-guard.ts`）：

| 要素 | 判定为缺失的条件 |
| --- | --- |
| `summary` | 空串 / 全空白 |
| `verified` | 非数组或**空数组** |
| `tried_actions` | 非数组（空数组合法——首轮确实没尝试过动作） |
| `unmet_demand` | **空串算缺失**（服务端对「无诉求」要给「无」之类占位） |
| `suggested_action` | 空串 |
| `emotion` | 缺 `level` 或 `intensity` |
| `turn_count` | `null` / `undefined`（`0` 合法） |

缺字段时：
1. 整卡换成 `data-testid="context-guard-error"`，标题「上下文生成异常，请联系技术支持」；
2. 列出**具体缺了哪几项**（坐席能直接告诉技术支持少了什么）；
3. 写埋点到 `sessionStorage['wankeai.telemetry.context']`，**只报一次**
   （按 `session_id + 缺失字段签名` 去重，否则重渲染会把埋点淹掉）。

**字段缺失时 `attachments=[]` 不算缺失**，也不触发守卫——附件是可选增强项。

### 3.2 子组件

| 组件 | 要素 | 要点 |
| --- | --- | --- |
| `VerifiedFacts` | `verified` | 类型标签 `order/logistics/product/policy` + 来源 `authority` |
| `TriedActions` | `tried_actions` | ok/fail 两态，失败项要显示原因 |
| `UnmetDemand` | `unmet_demand` | **警示色高亮**（任务书要求）；为「无」时用中性色 |
| `SuggestedAction` | `suggested_action` | 建议动作，可一键填入回复框 |
| `EmotionTag` | `emotion` | 三级情绪 + 强度条；`intensity` 是中文 `轻度/中度/强烈` |

## 5. 知识库（`kb/`）

### 5.1 `KbEditor` ★ 核心组件（单测覆盖率要求 ≥80%，实测 99%）

**作用**：知识条目新建 / 编辑，纯 Markdown 编辑器。

**要点**：
- **字数区间随类型变化**：商品 200–400 / 政策 100–300 / FAQ 50–200 / 长文档 300–500。
  超出显示「超过 X 字，入库时会被切分」，不足显示「不足 X 字」。
  字数口径是**去空白后的字符数**（`一二三\n四  五` 算 5 字）。
- **预览里屏蔽外链**：裸 URL 显示「[链接已屏蔽]」，`<a href>` 被转义。
  这是 HC-1 在编辑器侧的落地。
- **必填校验**：标题 / 正文 / 分类 / 权威来源，缺一个就禁用提交并列出缺什么。
- 编辑模式把旧内容压入 `history`，`version + 1`，且 **`review_status` 重置为 `PENDING`**
  ——改过的内容必须重新审核，不能沿用旧审批。

- **三态色**：绿（达标）/ 黄（接近）/ 红（未达标）；**等于目标值算达标**。

## 8. 引擎选型说明（对应「根据项目情况采用不同引擎」）

「界面引擎」在这里指渲染与交互的实现路线，本项目按页面类型分了三种，而不是一刀切：

| 页面类型 | 引擎路线 | 理由 |
| --- | --- | --- |
| 坐席工作台（实时） | Vue 响应式 + 原生 SSE + 虚拟滚动容忍 | 500 条消息 ≥50fps 靠的是「只追加不重排」，不需要虚拟列表 |
| 运营后台（表单密集） | Element Plus 表单/表格原生能力 | 自研表单控件的可访问性与校验成本远高于收益 |
| 数据看板（图形） | ECharts 5 Canvas 渲染 | SVG 在 12 卡片 + 趋势图下 DOM 节点过多 |

**为什么不用**：
- 微前端：只有两个系统、13 个页面，拆分反而增加联调面。
- WebSocket：任务书明确要求 SSE，且坐席台的实时性需求是单向推送，SSE 足够且断线重连更简单。
- 自研组件库：Element Plus 已覆盖 90% 场景，自研只剩维护成本。

## 9. 新增组件的检查清单

提 PR 前逐项确认：

- [ ] 根节点有语义类名，内部用 `&__xxx`，状态用 `--xxx`
- [ ] 颜色/间距/字号取自 `tokens.scss`，无内联 style
- [ ] **三态齐全**：loading / empty / error（用 `PageState`）
- [ ] **HC-1**：不渲染 `<a href>`，图片不可点击，文本不含外链
- [ ] **HC-2**：不展示完整手机号/姓名/订单号，用 `utils/format.ts` 的 `mask*`
- [ ] **HC-3**：库存/价格/物流单号必须来自接口，不写死
- [ ] 异步有 loading，超 1 秒用骨架屏
- [ ] 有单测（核心组件覆盖率 ≥80%）
- [ ] `npm run typecheck` + `npm run lint:compliance` 通过
