## 3. 统一接入要求（项目组需满足）

| 要求 | 说明 | 责任方 |
|---|---|---|
| HTTPS 域名 | 必须是已备案的 HTTPS 域名，用于接收平台回调 | 项目组提供域名，本店协助备案核验 |
| 固定出口 IP | 每环境最多 5 个，需加入平台白名单 | 项目组提供，本店提交 |
| 回调响应时效 | 3 秒内返回 HTTP 200，否则平台重推 | 项目组实现 |
| 消息去重 | 按 `msg_id` 去重，防止重推造成重复回复 | 项目组实现 |
| Token 刷新 | 各平台 access_token 有效期不同，需自动刷新 | 项目组实现 |
| 授权续期 | 授权有效期通常 1 年，到期前 15 天续期 | 本店 IT 负责提醒，项目组配合 |

## 4. 交付方式与安全要求

1. **AppSecret / Secret 等凭证**：**不写入本文档、不发群、不邮件明文**。按《商家资料索取清单》第四节要求，走**加密压缩包 + 单独渠道发密码**，使用企业微信文件传输或本店自有云盘，保留传输记录。
2. **店铺主账号**：**不向项目组提供**。项目组仅通过 OAuth 应用级授权获取 access_token，主账号始终保留在本店。
3. **权限最小化**：仅申请客服消息读写所需的最小权限集，不申请商品管理、订单发货、资金等无关权限。
4. **授权可回收**：本店可随时在开放平台撤销授权；项目结束后须主动解除授权并提供截图确认。

## 5. 例外情形

1. **平台政策变更**：各开放平台的权限包与审核规则可能随时调整，本店无法保证审核周期绝对准确，实际以平台通知为准。
2. **抖音服务商认证风险**：若认证未通过，抖音小店渠道将无法接入。**替代方案**：降级为「抖音渠道仅提供 FAQ 应答，不接入实时消息」，或改用抖店的第三方客服 SaaS 中转。
3. **微信客服接待人员上限**：企业微信对微信客服的接待人员数量有上限（默认 100 人），若坐席规模超出需申请扩容。
4. **历史授权记录**：2024 年以前的平台授权记录因平台侧已清理，本店无法提供。
5. **测试环境**：各平台的**沙箱环境**能力不一致（如拼多多沙箱功能有限），部分联调需在测试店铺的真实环境中进行。
