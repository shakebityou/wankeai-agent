### 0.3 鉴权方式

本店接口统一采用**双因子鉴权**：

| 因子 | 形式 | 说明 |
|---|---|---|
| 应用级 Token | 请求头 `X-Internal-Token` | 长期有效，按调用方分配，可随时吊销 |
| 请求签名 | 请求头 `X-Signature` | 每次请求计算，防止重放 |

**签名算法**：

```
sign_str = app_id + timestamp + nonce + body_sha256
X-Signature = HMAC-SHA256(sign_str, app_secret)   # 十六进制小写
```

**请求头示例**：

```http
X-Internal-Token: tk_live_9f2a7c81d4e6b350
X-App-Id: dsh_agent_001
X-Timestamp: 1767225600
X-Nonce: 8f2a7c81d4e6b350
X-Signature: 3c9f1a7e2b8d4f60a1c5e9d3b7f2a8c4e6d0b1f5a9c3e7d2b6f0a4c8e1d5b9f3
Content-Type: application/json; charset=utf-8
```

**鉴权约束**：

- `X-Timestamp` 与服务器时间偏差不得超过 **300 秒**，否则拒绝。
- `X-Nonce` 在 300 秒内不可重复，重复即视为重放，返回 `40101`。
- Token 泄露需立即通知本店 IT 吊销并重新签发。
- `app_secret` 不得硬编码在客户端或提交到代码仓库，需通过环境变量或密钥管理服务注入。

### 0.4 通用请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `app_id` | Header | string | 是 | 应用标识，由本店分配 |
| `X-Internal-Token` | Header | string | 是 | 应用级 Token |
| `X-Timestamp` | Header | int | 是 | Unix 秒级时间戳 |
| `X-Nonce` | Header | string | 是 | 16–32 位随机串 |
| `X-Signature` | Header | string | 是 | HMAC-SHA256 签名 |

### 0.5 通用响应结构

**成功响应**：

```json
{
  "code": 0,
  "message": "success",
  "request_id": "req_8f2a7c81d4e6b350",
  "data": { }
}
```

**失败响应**：

```json
{
  "code": 40401,
  "message": "order not found",
  "request_id": "req_8f2a7c81d4e6b350",
  "data": null
}
```

**通用字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 0 表示成功，非 0 为错误码（见 0.7） |
| `message` | string | 错误描述，成功时为 `success` |
| `request_id` | string | 本次请求唯一标识，排障时提供给本店 IT |
| `data` | object/array/null | 业务数据，失败时为 `null` |

### 0.6 限流阈值

| 接口 | QPS 上限 | 单应用日调用上限 | 突发额度 |
|---|---|---|---|
| 订单查询 | 20 | 200,000 | 允许 2 倍突发 10 秒 |
| 物流轨迹查询 | 20 | 200,000 | 允许 2 倍突发 10 秒 |
| 库存查询 | 50 | 500,000 | 允许 3 倍突发 10 秒 |
| 商品信息读取 | 30 | 300,000 | 允许 2 倍突发 10 秒 |
| 工单创建 | 5 | 20,000 | 不允许突发 |
| 平台客服消息收发 | 30 | 500,000 | 允许 2 倍突发 10 秒 |

**限流响应**：超限返回 HTTP `429`，响应体 `code` 为 `42901`，并携带响应头：

```http
X-RateLimit-Limit: 20
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1767225601
Retry-After: 1
```

**限流说明**：限流按 `app_id` 维度统计，测试环境与生产环境独立计算。测试环境 QPS 上限为生产环境的 1/5。需要提额需提前 3 个工作日申请。

### 0.7 通用错误码

| 错误码 | HTTP | 含义 | 处理建议 |
|---|---|---|---|
| `0` | 200 | 成功 | — |
| `40001` | 400 | 请求参数缺失或格式错误 | 检查必填参数 |
| `40002` | 400 | 参数值非法（如 order_no 长度不符） | 校验参数取值范围 |
| `40101` | 401 | 签名校验失败或 Nonce 重放 | 重新计算签名，更换 Nonce |
| `40102` | 401 | Token 无效或已吊销 | 联系本店 IT 换发 Token |
| `40103` | 401 | 时间戳偏差超过 300 秒 | 校准服务器时间（建议 NTP） |
| `40301` | 403 | 无该数据权限（如跨店铺查询） | 确认查询范围 |
| `40401` | 404 | 资源不存在（订单/商品/SKU） | 核对单号或编码 |
| `40901` | 409 | 重复请求（幂等冲突） | 复用原 `request_id` 查询结果 |
| `42901` | 429 | 触发限流 | 按 `Retry-After` 退避重试 |
| `50001` | 500 | 服务内部错误 | 携带 `request_id` 联系本店 IT |
| `50301` | 503 | 服务暂时不可用（维护/过载） | 指数退避重试，最多 3 次 |
| `50401` | 504 | 上游超时（ERP/快递商） | 退避重试；持续失败联系本店 IT |

### 0.8 暂不接入的能力（重要约束）

以下能力**接口定义保留、字段占位保留，但本期不实现对接**。项目组在开发时**遇到相关场景应直接绕过**，不要让对话流程依赖它们：

| 能力 | 保留位置 | 本期处理方式 |
|---|---|---|
| **跳转淘宝/拼多多等平台**（商品链接、店铺链接、活动链接、优惠券领取链接） | `msg_type = GOODS` / `CARD`；订单卡片、商品卡片的跳转字段 | **不接入**。客服回复一律使用**纯文字引导**（如「在店铺首页『领券中心』可领取」「您可以搜一下这个款」），**不生成、不发送任何外链或跳转卡片** |
| 小程序 / H5 落地页唤起 | `handoff_url` 等 URL 字段 | **不接入**。`handoff_url` 仅作字段占位，实际转人工通过工单系统完成 |
| 平台内商品卡片自动渲染 | 消息接口的 `CARD`/`GOODS` 类型 | **不接入**。`msg_type` 实际只使用 `TEXT` 与 `IMAGE` |

**对知识库与话术的约束**：所有 FAQ、商品知识卡、会话语料中的客服话术**不得出现「我把链接发您」「点这里跳转」一类表述**，应改为描述平台内可自行完成的操作路径。

**原因**：跳转类能力涉及各平台开放平台的额外权限与审核（见 `docs/渠道接入资质说明.md`），且属于二期范围；本期目标是跑通「理解—检索—回答—转人工」主链路，跳转不影响主链路验收。

## 1. 订单查询接口

**用途**：查询订单状态、金额、商品明细与物流摘要。字段命名与项目文档第 3.4 节完全一致。

### 1.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口地址 | `/api/v1/order/query` |
| 请求方式 | `GET` |
| 鉴权方式 | `X-Internal-Token` + `X-Signature` |
| 数据权限 | 只读 |
| 幂等性 | 天然幂等 |
| 测试环境 | `https://open-test.wankeai.example.com/api/v1/order/query` |

### 1.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `order_no` | string | 条件必填 | 订单号，12 位数字。与 `buyer_id` 至少传一个 |
| `buyer_id` | string | 条件必填 | 买家标识。与 `order_no` 至少传一个 |
| `channel` | string | 否 | 渠道：`TAOBAO`/`TMALL`/`PDD`/`DOUYIN`/`WECHAT`，不传则全渠道 |
| `page` | int | 否 | 页码，默认 1。仅在按 `buyer_id` 查询时生效 |
| `page_size` | int | 否 | 每页条数，默认 20，最大 50 |

### 1.3 请求示例

```http
GET /api/v1/order/query?order_no=202501150001&buyer_id=buyer_123 HTTP/1.1
Host: open.wankeai.example.com
X-Internal-Token: tk_live_9f2a7c81d4e6b350
X-App-Id: dsh_agent_001
X-Timestamp: 1767225600
X-Nonce: 8f2a7c81d4e6b350
X-Signature: 3c9f1a7e2b8d4f60a1c5e9d3b7f2a8c4e6d0b1f5a9c3e7d2b6f0a4c8e1d5b9f3
```

### 1.4 响应示例

```json
{
  "code": 0,
  "message": "success",

  "data": {

      "total": 199.00,

    },
    "items": [
      { "sku_id": "WK-BEAR-15", "title": "奶油小熊 15cm 挂件", "qty": 1, "price": 52.00 }

    "logistics": {
      "company": "中通",

      "name": "张**",

    }
  }

```

### 1.5 字段字典

| 字段 | 类型 | 说明 |
|---|---|---|
| `order_no` | string | 订单号，12 位数字 |
| `status` | string | 订单状态：`CREATED`/`PAID`/`SHIPPED`/`DELIVERED`/`CLOSED` |
| `buyer_id` | string | 买家标识（脱敏后的稳定 ID） |
| `channel` | string | 渠道：`TAOBAO`/`TMALL`/`PDD`/`DOUYIN`/`WECHAT` |
| `created_at` | string | 下单时间，`yyyy-MM-dd HH:mm:ss` |
| `paid_at` | string | 支付时间，未支付为 `null` |
| `amount.total` | decimal | 订单原价合计 |
| `amount.discount` | decimal | 优惠合计（券 + 满减） |
| `amount.freight` | decimal | 运费 |
| `amount.paid` | decimal | 实付金额 |
| `items[].sku_id` | string | SKU 编码，与商品主数据表一致 |
| `items[].title` | string | 商品名称 |
| `items[].qty` | int | 购买数量 |
| `items[].price` | decimal | 成交单价 |
| `logistics.company` | string | 快递公司名称 |
| `logistics.tracking_no` | string | 运单号 |
| `logistics.latest.time` | string | 最新物流时间 |
| `logistics.latest.desc` | string | 最新物流描述 |
| `estimated_arrival` | string | 预计到达日期 `yyyy-MM-dd`，无数据为 `null` |
| `receiver.name` | string | 收货人姓名，**已脱敏** |
| `receiver.phone` | string | 收货人手机号，**已脱敏** |
| `receiver.address` | string | 收货地址，**仅保留省市级** |

> **脱敏强制要求**：本接口返回的收货人信息必须按《商家资料索取清单》第四节规则脱敏后返回。`receiver.phone` 保留前 3 后 4 位，`receiver.name` 保留姓氏，`receiver.address` 仅保留省市级。**接口不得返回完整手机号与完整地址**，智能客服不需要该精度。

### 1.6 错误码

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| `40001` | 未传 `order_no` 与 `buyer_id` | 至少传一个 |
| `40002` | `order_no` 格式不符（非 12 位数字） | 校验格式 |
| `40401` | 订单不存在 | 核对单号，或确认是否跨店铺 |
| `40301` | 无该订单数据权限 | 确认 buyer 归属 |

## 2. 物流轨迹查询接口

**用途**：查询快递节点轨迹，用于物流类咨询与「签收未收到」核查。

### 2.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口地址 | `/api/v1/logistics/track` |
| 请求方式 | `GET` |
| 鉴权方式 | `X-Internal-Token` + `X-Signature` |
| 数据权限 | 只读 |
| 幂等性 | 天然幂等 |
| 测试环境 | `https://open-test.wankeai.example.com/api/v1/logistics/track` |

### 2.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `tracking_no` | string | 条件必填 | 运单号。与 `order_no` 至少传一个 |
| `order_no` | string | 条件必填 | 订单号，传此参数时服务端自动解析运单号 |
| `company` | string | 否 | 快递公司编码：`ZTO`/`YTO`/`SF`，不传则自动识别 |

### 2.3 请求示例

```http
GET /api/v1/logistics/track?order_no=202501150001 HTTP/1.1
Host: open.wankeai.example.com
X-Internal-Token: tk_live_9f2a7c81d4e6b350
X-Timestamp: 1767225600
X-Nonce: 8f2a7c81d4e6b350
X-Signature: 3c9f1a7e2b8d4f60a1c5e9d3b7f2a8c4e6d0b1f5a9c3e7d2b6f0a4c8e1d5b9f3
```

### 2.4 响应示例

```json
{
  "code": 0,
  "message": "success",
  "request_id": "req_8f2a7c81d4e6b350",
  "data": {
    "order_no": "202501150001",
    "company": "中通",
    "company_code": "ZTO",
    "tracking_no": "ZT123456789",
    "status": "IN_TRANSIT",
    "latest": { "time": "2025-01-17 09:20", "desc": "已到达【杭州转运中心】" },
    "estimated_arrival": "2025-01-19",
    "traces": [
      { "time": "2025-01-16 18:05", "desc": "【杭州转运中心】已到达", "status": "IN_TRANSIT" },
      { "time": "2025-01-17 09:20", "desc": "已到达【杭州转运中心】", "status": "IN_TRANSIT" },
      { "time": "2025-01-18 08:30", "desc": "【杭州市西湖区】派送中", "status": "OUT_FOR_DELIVERY" },
      { "time": "2025-01-18 14:12", "desc": "已签收，签收人：本人", "status": "DELIVERED" }
    ],
    "signed": true,
    "signed_at": "2025-01-18 14:12"
  }
}
```

### 2.5 字段字典

| 字段 | 类型 | 说明 |
|---|---|---|
| `order_no` | string | 关联订单号 |
| `company` | string | 快递公司名称 |
| `company_code` | string | 快递公司编码：`ZTO`/`YTO`/`SF` |
| `tracking_no` | string | 运单号 |
| `status` | string | 物流状态：`PENDING`/`COLLECTED`/`IN_TRANSIT`/`OUT_FOR_DELIVERY`/`DELIVERED`/`EXCEPTION`/`RETURNED` |
| `latest` | object | 最新一条轨迹，结构与 `traces[]` 一致 |
| `estimated_arrival` | string | 预计到达日期，无数据为 `null` |
| `traces[].time` | string | 轨迹时间 |
| `traces[].desc` | string | 轨迹描述（**原文返回，不改写**） |
| `traces[].status` | string | 该节点状态 |
| `signed` | bool | 是否已签收 |
| `signed_at` | string | 签收时间，未签收为 `null` |

> **注意**：`traces[].desc` 为快递公司原始轨迹文本，**不做改写**。智能客服在引用时需注意原文可能含分拨中心名称等敏感位置信息，对外答复时按业务口径转述。

### 2.6 错误码

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| `40001` | 未传 `tracking_no` 与 `order_no` | 至少传一个 |
| `40401` | 无物流记录（订单未发货） | 提示「尚未发货」 |
| `50401` | 快递商接口超时 | 退避重试，最多 3 次 |

## 3. 库存查询接口

**用途**：查询 SKU 实时库存与预售状态，用于「有没有货/什么时候发」类咨询。

### 3.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口地址 | `/api/v1/inventory/query` |
| 请求方式 | `GET` |
| 鉴权方式 | `X-Internal-Token` + `X-Signature` |
| 数据权限 | 只读 |
| 幂等性 | 天然幂等 |
| 测试环境 | `https://open-test.wankeai.example.com/api/v1/inventory/query` |

### 3.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sku_ids` | string | 是 | SKU 编码，多个用英文逗号分隔，单次最多 50 个 |
| `with_presale` | bool | 否 | 是否返回预售信息，默认 `true` |

## 6. 平台客服消息收发接口

**用途**：在五个渠道内收发用户消息，是智能客服与用户对话的通道。

### 6.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口地址 | `/api/v1/message/send`（发送）；`/api/v1/message/callback`（接收回调） |
| 请求方式 | `POST`（发送）；平台推送（接收） |
| 鉴权方式 | 发送：`X-Internal-Token` + `X-Signature`；接收：平台签名校验 |
| 数据权限 | 读写 |
| 幂等性 | 发送按 `msg_id` 幂等 |
| 测试环境 | `https://open-test.wankeai.example.com/api/v1/message/send` |

### 6.2 渠道对接方式

| 渠道 | 对接方式 | 授权形式 | 备注 |
|---|---|---|---|
| 淘宝 | 淘宝开放平台「千牛客服」消息 API | 应用授权 + 店铺绑定 | 需店铺主账号授权 |
| 天猫 | 同淘宝（天猫并入淘宝开放平台） | 同上 | — |
| 拼多多 | 拼多多开放平台「客服消息」API | 应用授权 | 需申请客服消息权限包 |
| 抖音小店 | 抖店开放平台「IM 客服」API | 应用授权 + 店铺绑定 | 需通过抖店服务商认证 |
| 微信客服 | 企业微信「微信客服」API | 企业微信应用 + Secret | 需配置回调 URL 与可信 IP |

> **各平台授权说明**：五个渠道的授权需**分别申请**，授权有效期与平台政策相关（通常 1 年），到期前需提前 15 天续期。授权凭证由本店 IT 统一保管，不写入代码仓库。

### 6.3 发送消息 - 请求参数（Body）

| `reply_to` | string | 否 | 回复的消息 ID |

平台将用户消息推送至 `/api/v1/message/callback`，结构如下：

```json
{
```

### 6.8 错误码

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| `40001` | 缺少必填字段 | 补齐 |
| `40102` | 渠道授权失效或过期 | 重新授权 |
| `40301` | 该渠道无消息权限 | 申请对应权限包 |
| `40401` | 会话不存在或已关闭 | 新建会话 |
| `40901` | `msg_id` 重复 | 复用原结果，不重发 |
| `42901` | 触发限流 | 退避重试 |
| `50001` | 平台侧异常 | 携带 `request_id` 联系本店 IT |

## 附录 C：异常情形与降级策略

| 情形 | 表现 | 降级策略 |
|---|---|---|
| ERP 上游超时 | `50401` | 退避重试 3 次；仍失败则答复「系统查询中，请稍候」并转人工 |
| 快递商接口不可用 | `50401` | 降级为返回订单内缓存的物流摘要；无缓存则转人工 |
| 库存接口不可用 | `50301` | 降级为答复「库存实时同步中」并引导加购提醒 |
| 工单接口不可用 | `50301` | 记录本地队列稍后重试，同时直接展示人工客服联系方式 |
| 消息发送失败 | `50001`/`42901` | 退避重试 2 次；仍失败则记录失败消息并告警 |
| 渠道授权过期 | `40102` | 立即告警本店 IT，同时该渠道降级为纯 FAQ 应答 |
| 触发限流 | `42901` | 按 `Retry-After` 退避；持续限流需申请提额 |

## 附录 D：安全与合规要求

1. **脱敏强制**：订单接口返回的收货人信息必须脱敏；日志中禁止打印完整手机号、完整地址、完整订单号。
2. **数据用途限定**：接口数据仅用于本项目知识库建设与实时应答，**不得用于任何模型训练**。
3. **Token 管理**：Token 与 `app_secret` 不得硬编码，需通过环境变量或密钥管理服务注入；离职人员需立即回收。
4. **日志留存**：接口调用日志（含 `request_id`）留存不少于 6 个月，用于排障与审计。
5. **传输加密**：全部接口强制 HTTPS（TLS 1.2+），禁止 HTTP 明文调用。
6. **访问审计**：所有写接口（工单创建、消息发送）需记录操作人与时间，留存不少于 1 年。
7. **数据删除**：项目结束后按《商家资料索取清单》第四节约定删除数据，并出具删除确认函。
