## 一、申请总览

依据《商家资料索取清单》第三节「接口与权限清单（IT 部门专项）」的 7 项要求，本店逐项确认可提供的形式与前置条件如下：

| 序号 | 权限名称 | 读写 | 本店可提供形式 | 状态 | 预计开通周期 |
|---|---|---|---|---|---|
| 1 | 订单查询 | 只读 | API（REST）+ 只读库账号（备选） | ✅ 可提供 | 3 个工作日 |
| 2 | 物流轨迹查询 | 只读 | API（聚合快递鸟 + 自建双通道） | ✅ 可提供 | 3 个工作日 |
| 3 | 库存查询 | 只读 | API（REST）+ 只读视图（备选） | ✅ 可提供 | 3 个工作日 |
| 4 | 商品信息读取 | 只读 | API（REST）+ 每日定时导出（备选） | ✅ 可提供 | 3 个工作日 |
| 5 | 工单创建 | 写入 | API（REST），按 session_id 幂等 | ✅ 可提供 | 5 个工作日 |
| 6 | 平台客服消息收发 | 读写 | 五渠道开放平台授权（分别申请） | ⚠️ 部分渠道需平台审核 | 淘宝/天猫 5 天；拼多多 7 天；抖音 10 天；微信客服 7 天 |
| 7 | 测试环境访问 | 只读+写入（测试数据） | VPN + 跳板机 + 测试库账号 | ✅ 可提供 | 5 个工作日 |

**总体结论**：7 项权限**本店均可提供**，其中第 6 项（平台客服消息收发）需依赖各平台开放平台的审核时效，**是最长的关键路径**，建议项目组优先启动该渠道的授权申请。

## 二、逐项说明

### 权限 1：订单查询（只读）

| 项目 | 内容 |
|---|---|
| **用途** | 查询订单状态、金额、商品明细，支撑 FR-04 订单与物流查询功能；客服答复「我的订单到哪了」「订单什么状态」类咨询 |
| **期望形式** | **首选 API**：`GET /api/v1/order/query`；**备选**：ERP 中间库只读账号（视图 `v_order_query`） |
| **数据范围** | 本店五个渠道（淘宝/天猫/拼多多/抖音小店/微信客服）的全部订单，仅限本店铺 |
| **字段范围** | `order_no`、`status`、`items[]`（`sku_id`/`title`/`qty`/`price`）、`logistics`、`estimated_arrival`、`receiver`（**脱敏后**） |
| **鉴权方式** | 应用级 `X-Internal-Token` + 请求签名 `X-Signature`（HMAC-SHA256） |
| **限流** | 20 QPS，日调用上限 200,000 |
| **脱敏要求** | 接口侧强制脱敏：手机号保留前 3 后 4 位、姓名保留姓氏、地址仅到省市级。**不返回完整手机号与完整地址** |
| **不可提供** | 买家身份证号、银行卡号、支付流水号、平台内部风控标记 |
| **前置条件** | 项目组提供固定出口 IP（每环境最多 5 个）；签署《数据安全承诺书》 |
| **备注** | 只读账号不可执行任何写操作，数据库层面以 `SELECT` 权限授权，禁用 `UPDATE`/`DELETE`/`DROP` |

### 权限 2：物流轨迹查询

| 项目 | 内容 |
|---|---|
| **用途** | 查询快递节点轨迹，支撑物流类咨询（本店咨询量 Top 3）、「签收未收到」核查、丢件破损流程 |
| **期望形式** | **API**：`GET /api/v1/logistics/track`；底层对接**快递鸟 + 快递 100 双通道**，并保留合作快递（中通/圆通/顺丰）直连账号 |
| **覆盖快递** | 中通、圆通、顺丰（覆盖本店 98% 以上订单） |
| **字段范围** | `company`、`tracking_no`、`status`、`traces[]`（`time`/`desc`/`status`）、`signed`、`signed_at` |
| **鉴权方式** | 同权限 1（Token + 签名） |
| **限流** | 20 QPS，日调用上限 200,000 |
| **不可提供** | 快递商接口的原始密钥；快递员个人联系方式 |
| **前置条件** | 快递鸟/快递 100 账号由本店提供并承担费用；项目组不得转售或二次分发轨迹数据 |
| **备注** | 轨迹文本为快递公司原文，含分拨中心名称；对外答复时需按业务口径转述，不直接朗读原文 |

### 权限 3：库存查询（只读）

| 项目 | 内容 |
|---|---|
| **用途** | 查询 SKU 实时库存与预售状态，答复「还有货吗」「什么时候发货」类咨询 |
| **期望形式** | **首选 API**：`GET /api/v1/inventory/query`；**备选**：ERP 只读视图 `v_inventory_realtime`（15 分钟刷新） |
| **数据范围** | 全部 74 个在售 SKU 的库存状态（现货/预售/缺货）、可售数量、预售天数、承诺发货时长 |
| **鉴权方式** | 同权限 1 |
| **限流** | 50 QPS，日调用上限 500,000 |
| **同步时效** | 接口为实时查询；只读视图为 15 分钟延迟。**实时性要求高时用接口** |
| **不可提供** | 采购成本价、供应商信息、仓库具体货位、安全库存阈值 |
| **前置条件** | 无特殊前置，随权限 1 一并开通 |
| **备注** | 库存与价格属「会变的数字」，按项目文档第 4.1 节原则**走接口不进向量库** |

### 权限 4：商品信息读取（只读）

| 项目 | 内容 |
|---|---|
| **用途** | 同步商品属性（尺寸、材质、填充物、适用年龄、洗护方式、包装形式等），作为 RAG 商品知识源；生成商品知识卡 |
| **期望形式** | **首选 API**：`GET /api/v1/product/detail`（支持 `updated_since` 增量同步）；**备选**：每日定时导出 CSV |
| **数据范围** | 全部 74 个 SKU 的 14 个属性字段（与 `data/商品主数据表.csv` 一致） |
| **鉴权方式** | 同权限 1 |
| **限流** | 30 QPS，日调用上限 300,000 |
| **不可提供** | 采购价、供应商、生产成本、未上市款式的设计稿 |
| **前置条件** | 无特殊前置 |
| **备注** | 本店已先行提供静态商品主数据（S-01/S-11），本权限用于**上线后的持续同步** |

### 权限 5：工单创建（写入）

| 项目 | 内容 |
|---|---|
| **用途** | 转人工时自动创建工单，携带会话摘要与实体，避免用户重复描述；支撑项目文档第 5.5 节的 5 类转人工触发 |
| **期望形式** | **API**：`POST /api/v1/ticket/create`，**按 `session_id` 幂等** |
| **写入字段** | `session_id`、`buyer_id`、`reason`、`summary`、`entities`、`tried_actions`、`priority`、`channel`、`transcript` |
| **落库系统** | 本店自建客服工单系统（`kf.wankeai.example.com`），坐席工作台可实时看到新工单 |
| **鉴权方式** | 同权限 1 |
| **限流** | 5 QPS，日调用上限 20,000（写入接口额度较低，防误刷） |
| **权限边界** | **仅允许创建工单**，不允许修改工单状态、不允许关闭工单、不允许查看他人工单。工单状态流转由坐席在人工工作台操作 |
| **不可提供** | 工单的批量删除、状态改写、跨店铺查询权限 |
| **前置条件** | 项目组需提供工单内容的字段映射确认（`reason` 枚举需与人工工作台一致） |
| **备注** | 写接口需记录操作日志（操作人、时间、`request_id`），留存不少于 1 年 |

### 权限 6：平台客服消息收发

| 项目 | 内容 |
|---|---|
| **用途** | 在五个渠道内收发用户消息，是智能客服与用户对话的**唯一通道**；对应项目文档 FR-01（多轮对话）与 FR-05（多渠道接入） |
| **期望形式** | 各平台开放平台的应用授权 + 店铺绑定 + 客服消息权限包 |
| **渠道明细** | 见下表 |

| 渠道 | 开放平台 | 所需权限 | 授权主体 | 审核周期 | 关键依赖 |
|---|---|---|---|---|---|
| 淘宝 | 淘宝开放平台 | 「千牛客服」消息读写 | 店铺主账号 | 5 个工作日 | 应用需通过淘宝审核 |
| 天猫 | 淘宝开放平台 | 同淘宝 | 店铺主账号 | 5 个工作日 | 天猫并入淘宝开放平台 |
| 拼多多 | 拼多多开放平台 | 「客服消息」权限包 | 店铺主账号 | 7 个工作日 | 需申请客服消息权限包 |
| 抖音小店 | 抖店开放平台 | 「IM 客服」读写 | 店铺主账号 | 10 个工作日 | 需通过抖店服务商认证 |
| 微信客服 | 企业微信 | 「微信客服」API | 企业微信管理员 | 7 个工作日 | 需配置回调 URL 与可信 IP |

| 项目 | 内容 |
|---|---|
| **鉴权方式** | 发送：`X-Internal-Token` + `X-Signature`；接收：平台回调签名校验 |
| **限流** | 30 QPS，日调用上限 500,000 |
| **回调要求** | HTTPS 固定域名；3 秒内返回 HTTP 200；按 `msg_id` 去重 |
| **权限边界** | 仅允许收发**本店铺**的客服会话消息，不可访问其他店铺、不可导出用户完整资料 |
| **不可提供** | 平台账号密码；店铺主账号的登录凭证（仅提供应用级授权，主账号保留在本店） |
| **前置条件** | ① 项目组提供**已备案的 HTTPS 域名**与固定出口 IP；② 回调 URL 需先在本店侧完成联调；③ 各渠道授权需**分别申请**，授权有效期通常 1 年，到期前 15 天续期 |
| **备注** | **这是关键路径最长的一项**。抖音小店需服务商认证，建议第 1 周即启动；其余渠道可并行申请 |

## 五、审批与开通流程

1. **提交申请**：项目组 PO 提交本清单（含联调人员名单与出口 IP），本店 IT 部受理。
2. **安全审核**：本店 IT 部与法务审核数据用途、签署《数据安全承诺书》。
3. **开通账号**：按第一节的预计周期逐项开通；账号密码走安全渠道交付。
4. **联调验证**：项目组按 `docs/接口对接说明书.md` 附录 B 的联调检查清单逐项验证。
5. **生产切换**：联调通过后，本店 IT 部签发生产 Token，并加入生产 IP 白名单。

**驳回与整改**：若项目组的数据用途超出「知识库建设与实时应答」范围，或要求提供本文档标注「不可提供」的字段，本店 IT 部有权驳回并要求整改。

## 六、风险提示

| 风险 | 影响 | 建议 |
|---|---|---|
| 抖音小店渠道需服务商认证，审核周期 10 天 | 影响上线时间 | **第 1 周即启动申请** |
| 平台授权有效期通常 1 年 | 到期未续期将导致渠道掉线 | 记录到期日，提前 15 天续期 |
| 测试环境数据每日重置 | 联调需可复现的测试数据 | 使用第 3.2 节的固定测试订单号 |
| 写接口额度较低（工单 5 QPS） | 大促期间可能触发限流 | 实现退避重试与本地队列 |
| 出口 IP 白名单上限 5 个 | 人员变动需及时调整 | 指定专人管理白名单 |
